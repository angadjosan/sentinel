# Sentinel v0.1.0 Architecture Reference

**Date:** June 29, 2026
**Version:** v0.1.0
**Context:** System architecture and implementation reference for Sentinel, an LLM-powered application security platform designed for CI-native scanning.

## Overview
Sentinel is an LLM-powered security platform that focuses on context-aware reachability and exploitability rather than simple pattern matching. It ensures source code never leaves the user's environment.

## Architectural Invariants
1. **Channel separation:** Instruction and data tiers never mix.
2. **Runtime Oracle:** Findings are only "confirmed" via deterministic behavioral proof or sanitizer crash (not LLM assertion).
3. **Graph:** Acts as a navigation index, not a code mirror (no source text stored).
4. **Stateless Client:** The CLI maintains no local durable state.
5. **Privacy:** Source code never leaves the machine (CI runner/laptop).
6. **Freshness:** Content-addressed graph, reconciled on every run.

## Runtime Components
* **CLI (`cli/`):** TypeScript-based stateless client.
* **API (`api/`):** FastAPI control plane for metadata management.
* **Worker (`worker/`):** Analysis engine (graph construction, LLM agent, pentest).
* **Dashboard (`dashboard/`):** Next.js 15 UI for findings and analytics.

## Data Model
* Based on an SQLAlchemy ORM shared between the API and Worker.
* **Code Property Graph:** Composed of `Node` and `Edge` tables.
* **Identity:** Node IDs are line-number independent for stability across edits.

## Data Flows
* **Flow A (CI-native):** Pipeline runs entirely in the user's CI; emits SARIF + metadata.
* **Flow B (Cloud-backed):** CLI enqueues tasks via API; Worker executes tasks locally via Docker.
* **Flow C (Pentest):** Confirms findings via MicroVM/fuzzing against a plain or sanitizer build.
